## 🎯 修复策略

### 当前策略：逐个文件修复

**优点**：
- 精确控制
- 可以判断每个print的用途
- 避免误修复

**缺点**：
- 速度较慢
- 需要大量手动工作

### 推荐工作流程

1. **识别文件**：找到包含print的文件
2. **分析用途**：判断每个print是调试信息还是用户消息
3. **添加保护**：用#if DEBUG包裹调试print
4. **测试验证**：确保功能正常

## 🔧 修复模板

### 标准修复模板

```swift
// ❌ 修复前
print("调试信息: \(value)")

// ✅ 修复后
#if DEBUG
print("调试信息: \(value)")
#endif
```

### 多个print语句

```swift
// ❌ 修复前
print("步骤1")
print("步骤2")
print("步骤3")

// ✅ 修复后
#if DEBUG
print("步骤1")
print("步骤2")
print("步骤3")
#endif
```

### 使用Logger（推荐）

```swift
// ❌ 修复前
print("网络请求: \(url)")

// ✅ 修复后（推荐）
#if DEBUG
Logger.network.debug("网络请求: \(url)")
#endif
```

---

## ⚠️ 注意事项

1. **不要修复用户消息**
   - 如果print用于显示给用户，应该改为Toast/Alert
   - 不要用#if DEBUG包裹

2. **关键错误处理**
   - 使用Logger.error（会自动处理生产环境）
   - 或保留在生产环境

3. **测试每个修复**
   - DEBUG模式：确认日志正常
   - RELEASE模式：确认不输出
