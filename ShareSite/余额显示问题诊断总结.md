# 余额显示问题诊断总结

## 📅 日期
2025年11月2日

## 🔍 问题描述

用户报告App显示的虫遇能量余额为**176,757**，但通过Postman测试本地服务器显示余额为**496,229**。担心App连接到了错误的服务器。

## 🛠️ 诊断过程

### 1. 添加详细日志

在 `WalletService.swift` 中添加了详细的调试日志：
- 服务器URL日志
- 请求发送日志
- 响应数据日志
- 解析结果日志

在 `ProfileView.swift` 中添加了帖子数据日志：
- 用户帖子数量
- 每个帖子的图片信息

### 2. 实际测试结果

通过App日志发现：

```
🔧 [WalletService] 使用Info.plist服务器: http://121.40.184.29:3000
💰 [WalletService] 正在请求余额: http://121.40.184.29:3000/balance
📦 [WalletService] 收到原始数据: {"balance":180357,"currency":"CREDITS"}
✅ [WalletService] 余额解析成功: 180357 CREDITS
```

## ✅ 诊断结论

### 服务器连接正确

**App确实连接到了阿里云生产服务器** (`http://121.40.184.29:3000`)，配置完全正确。

### 余额差异原因

实际余额是 **180,357**，不是用户看到的176,757，也不是Postman测试的496,229。

可能的原因：
1. **积分被消耗** - 从496,229降到180,357，说明有约31.5万积分被使用
2. **正常业务消耗** - AI对话、图片识别、内容生成等功能都会消耗积分
3. **不同账户** - Postman测试可能使用了不同的 `X-App-Account-Token`

### 余额变化分析

- **Postman测试时**: 496,229 积分（本地开发服务器）
- **App实际显示**: 180,357 积分（阿里云生产服务器）
- **差值**: 约315,872 积分

这个差值说明：
- App连接的是**生产环境**（阿里云服务器）
- Postman测试的是**开发环境**（本地服务器）
- 两个环境的数据库是独立的
