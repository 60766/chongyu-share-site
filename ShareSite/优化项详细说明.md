# 优化项详细说明

## 1. IAP验证：App Store Server API验证

### 📋 当前状态

**当前实现方式：**
```javascript
// backend/server.js 第345-375行
app.post('/purchase/confirm', (req, res) => {
  const { productId, transactionId, receipt } = req.body || {}
  
  // TODO: verify with App Store Server API using receipt
  
  // 当前实现：基于Product ID映射
  const skuToCredits = {
    'com.lishilong.chongyu.100energy': 1800,
    'com.lishilong.chongyu.300energy': 6000,
    // ...
  }
  const credits = skuToCredits[productId]
  
  // 防重复：基于transactionId
  if (processedIapTransactions.has(transactionId)) {
    return res.json({ balance: wallet.balance })
  }
  
  // 直接充值，未验证receipt
  creditWallet(appAccountToken, credits, transactionId, ...)
})
```

**工作流程：**
1. iOS端发送：`productId` + `transactionId` + `receipt`（可选）
2. 后端检查：`transactionId` 是否已处理过
3. 后端映射：根据 `productId` 查找对应的虫洞币数量
4. 后端充值：直接充值，**未验证receipt的真实性**

### ⚠️ 潜在风险

**当前方案的风险：**
1. **无法验证购买真实性**
   - 用户可能伪造 `transactionId`
   - 用户可能重复使用已退款交易的 `transactionId`
   - 无法验证receipt是否来自Apple

2. **可能被滥用**
   - 恶意用户可能构造虚假的充值请求
   - 无法防止退款后继续使用虫洞币

3. **不符合Apple要求**
   - Apple要求服务器端验证receipt
   - 未验证可能导致应用被下架

### ✅ 建议方案：App Store Server API验证

**App Store Server API是什么？**
- Apple提供的服务器端API，用于验证应用内购买的真实性
- 可以验证receipt、检查交易状态、处理退款等

**实现方式：**
```javascript
// 伪代码示例
app.post('/purchase/confirm', async (req, res) => {
  const { productId, transactionId, receipt } = req.body || {}
  
  // 1. 调用App Store Server API验证receipt
  const verificationResult = await verifyWithAppStoreServerAPI({
    receipt: receipt,
    transactionId: transactionId,
    productId: productId
  })
  
  // 2. 检查验证结果
  if (!verificationResult.isValid) {
    return res.status(400).json({ error: 'invalid_receipt' })
  }
  
  // 3. 检查交易状态
  if (verificationResult.status !== 'ACTIVE') {
    return res.status(400).json({ error: 'transaction_not_active' })
  }
  
  // 4. 检查是否已处理过
  if (processedIapTransactions.has(transactionId)) {
    return res.json({ balance: wallet.balance })
  }
  
  // 5. 验证通过后充值
  const credits = skuToCredits[productId]
  creditWallet(appAccountToken, credits, transactionId, ...)
})
```

**优点：**
- ✅ 验证购买真实性
- ✅ 防止退款后继续使用
- ✅ 符合Apple要求
- ✅ 提高安全性

**缺点：**
- ❌ 需要额外的API调用（可能增加延迟）
- ❌ 需要处理Apple API的错误情况
- ❌ 实现复杂度较高

**为什么是"非阻塞"？**
- 当前方案在MVP阶段可以接受
- 有防重复机制（`processedIapTransactions`）
- 可以上线后再优化
- 但建议尽快实现，提高安全性

## 2. 管理员端点：添加身份验证

### 📋 当前状态

**当前实现：**
```javascript
// backend/server.js 第323-343行
app.post('/admin/set-balance', (req, res) => {
  const { appAccountToken, balance } = req.body || {}
  if (!appAccountToken || typeof balance !== 'number') {
    return res.status(400).json({ error: 'missing appAccountToken or balance' })
  }
  // 直接设置余额，无身份验证
  const wallet = getWallet(appAccountToken, { allowWelcome: false })
  wallet.balance = Math.max(0, balance)
  // ...
})
```

**问题：**
- ❌ **任何人都可以调用**：只要知道API地址就可以设置任意用户的余额
- ❌ **无身份验证**：没有检查调用者是否有权限
- ❌ **安全风险**：可能被恶意利用

### ⚠️ 潜在风险

**如果被恶意利用：**
1. 攻击者可以给自己设置无限余额
2. 攻击者可以给其他用户设置余额（恶意或善意）
3. 可能影响游戏平衡和经济系统

### ✅ 建议方案：添加身份验证

**方案1：API密钥验证**
```javascript
// 在环境变量中设置管理员密钥
const ADMIN_API_KEY = process.env.ADMIN_API_KEY || ''

app.post('/admin/set-balance', (req, res) => {
  // 1. 验证管理员密钥
  const apiKey = req.header('X-Admin-API-Key')
  if (apiKey !== ADMIN_API_KEY) {
    return res.status(401).json({ error: 'unauthorized' })
  }
  
  // 2. 继续原有逻辑
  const { appAccountToken, balance } = req.body || {}
  // ...
})
```

**方案2：IP白名单**
```javascript
const ADMIN_IP_WHITELIST = ['127.0.0.1', 'your-server-ip']

app.post('/admin/set-balance', (req, res) => {
  // 1. 检查IP地址
  const clientIP = req.ip || req.connection.remoteAddress
  if (!ADMIN_IP_WHITELIST.includes(clientIP)) {
    return res.status(403).json({ error: 'forbidden' })
  }
  
  // 2. 继续原有逻辑
  // ...
})
```

**方案3：JWT令牌验证**
```javascript
// 管理员登录后获得JWT令牌
app.post('/admin/login', (req, res) => {
  const { username, password } = req.body || {}
  // 验证用户名密码
  if (username === ADMIN_USERNAME && password === ADMIN_PASSWORD) {
    const token = jwt.sign({ role: 'admin' }, SECRET_KEY)
    return res.json({ token })
  }
  return res.status(401).json({ error: 'invalid_credentials' })
})

app.post('/admin/set-balance', authenticateAdmin, (req, res) => {
  // authenticateAdmin中间件验证JWT令牌
  // ...
})
```

**推荐方案：**
- **开发/测试环境：** API密钥验证（简单快速）
- **生产环境：** JWT令牌验证 + IP白名单（更安全）

**为什么是"非阻塞"？**
- 当前主要用于测试和调试
- 如果只在内部使用，风险较低
- 可以上线后再添加
- 但建议尽快实现，防止误操作或恶意利用

## 3. 数据存储：迁移到数据库

### 📋 当前状态

**当前实现：**
```javascript
// backend/server.js 第50-73行
// 数据存储在内存中（Map）
const wallets = new Map()
const transactions = []
const appleIdAccounts = new Map()
// ...

// 持久化到JSON文件
const DATA_FILE = 'server-data.json'
function saveToDisk() {
  fs.writeFileSync(DATA_FILE, JSON.stringify(serializeState(), null, 2))
}

// 每30秒自动保存
setInterval(() => {
  try { saveToDisk() } catch {}
}, 30_000)
```

**工作方式：**
1. 数据存储在内存（Map、Array）
2. 定期保存到JSON文件（`server-data.json`）
3. 启动时从JSON文件加载数据

### ⚠️ 当前方案的局限性

**1. 性能问题**
- **数据量大时：** JSON文件可能很大，读写慢
- **全量保存：** 每次保存都要序列化所有数据
- **内存占用：** 所有数据都在内存中

**2. 并发问题**
- **单进程：** 无法水平扩展（多服务器）
- **文件锁：** 多进程同时写入可能冲突
- **数据一致性：** 难以保证多服务器间数据一致

**3. 查询能力**
- **简单查询：** 只能遍历所有数据
- **复杂查询：** 难以实现（如：查询某时间段的交易）
- **索引：** 无法使用数据库索引

**4. 可靠性**
- **单点故障：** JSON文件损坏可能导致数据丢失
- **备份：** 需要手动备份
- **恢复：** 恢复数据较复杂

### ✅ 建议方案：迁移到数据库

**方案1：SQLite（轻量级）**
```javascript
const sqlite3 = require('sqlite3').verbose()
const db = new sqlite3.Database('chongyu.db')

// 创建表
db.serialize(() => {
  db.run(`CREATE TABLE IF NOT EXISTS wallets (
    token TEXT PRIMARY KEY,
    balance INTEGER,
    created_at INTEGER
  )`)
  
  db.run(`CREATE TABLE IF NOT EXISTS transactions (
    id TEXT PRIMARY KEY,
    token TEXT,
    type TEXT,
    amount INTEGER,
    ref TEXT,
    at INTEGER
  )`)
})

// 查询余额
function getWallet(token) {
  return new Promise((resolve, reject) => {
    db.get('SELECT * FROM wallets WHERE token = ?', [token], (err, row) => {
      if (err) reject(err)
      else resolve(row)
    })
  })
}
```

**优点：**
- ✅ 文件数据库，无需单独服务器
- ✅ 支持SQL查询
- ✅ 支持事务
- ✅ 性能比JSON文件好

**缺点：**
- ❌ 仍然有并发问题（多进程）
- ❌ 不适合大规模数据

**方案2：PostgreSQL（生产级）**
```javascript
const { Pool } = require('pg')
const pool = new Pool({
  host: 'localhost',
  database: 'chongyu',
  user: 'chongyu_user',
  password: 'password'
})

// 查询余额
async function getWallet(token) {
  const result = await pool.query(
    'SELECT * FROM wallets WHERE token = $1',
    [token]
  )
  return result.rows[0]
}
```

**优点：**
- ✅ 支持多服务器（水平扩展）
- ✅ 强大的查询能力
- ✅ 事务支持
- ✅ 数据一致性保证
- ✅ 备份和恢复工具完善

**缺点：**
- ❌ 需要单独的数据库服务器
- ❌ 配置和维护更复杂
- ❌ 成本更高

**方案3：MongoDB（NoSQL）**
```javascript
const { MongoClient } = require('mongodb')
const client = new MongoClient('mongodb://localhost:27017')

// 查询余额
async function getWallet(token) {
  const db = client.db('chongyu')
  const wallets = db.collection('wallets')
  return await wallets.findOne({ token })
}
```

**优点：**
- ✅ 灵活的文档结构
- ✅ 易于扩展
- ✅ 适合非结构化数据

**缺点：**
- ❌ 需要单独的数据库服务器
- ❌ 查询能力不如SQL数据库

### 📊 方案对比

| 方案 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| **JSON文件** | MVP/小规模 | 简单、无需配置 | 性能差、无法扩展 |
| **SQLite** | 中小规模 | 文件数据库、SQL支持 | 并发问题 |
| **PostgreSQL** | 生产环境 | 强大、可扩展 | 需要服务器 |
| **MongoDB** | 非结构化数据 | 灵活、易扩展 | 需要服务器 |

### 💡 迁移建议

**阶段1：当前（MVP）**
- ✅ 继续使用JSON文件
- ✅ 定期备份 `server-data.json`
- ✅ 监控文件大小和性能

**阶段2：用户增长（1000+用户）**
- 💡 考虑迁移到SQLite
- 💡 实现数据库查询接口
- 💡 逐步迁移数据

**阶段3：大规模（10000+用户）**
- 💡 迁移到PostgreSQL
- 💡 实现数据库集群
- 💡 优化查询性能

**为什么是"非阻塞"？**
- 当前用户量可能不大，JSON文件可以满足需求
- 迁移到数据库需要大量工作
- 可以等用户增长后再考虑
- 但建议提前规划，避免后期迁移困难
