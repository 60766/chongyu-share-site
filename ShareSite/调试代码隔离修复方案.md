## 🎯 修复策略

- 快速修复

- 代码会变长
- 需要手动检查每个print的用途

**优点**：
- 统一的日志管理
- 更好的日志分类
- 可以控制日志级别

**缺点**：
- 需要大量代码替换
- 可能影响现有逻辑

## 📝 修复规则

### 规则1：纯调试信息 → 添加#if DEBUG

```swift
// ❌ 修复前
print("用户token: \(token)")

// ✅ 修复后
#if DEBUG
print("用户token: \(token)")
#endif
```

### 规则2：错误信息 → 使用Logger.error

```swift
// ❌ 修复前
print("❌ 错误: \(error)")

// ✅ 修复后
Logger.error("错误", error: error)
```

### 规则3：网络请求 → 使用Logger.network

```swift
// ❌ 修复前
print("📥 HTTP status: \(statusCode)")

// ✅ 修复后
#if DEBUG
Logger.network.debug("HTTP status: \(statusCode)")
#endif
```

## 🚀 快速修复脚本

### 自动添加#if DEBUG保护

```bash
# 查找未保护的print语句
find 虫遇 -name "*.swift" -exec grep -l "print(" {} \; | while read file; do
    # 检查是否已有#if DEBUG
    if ! grep -q "#if DEBUG" "$file"; then
        echo "需要修复: $file"
    fi
done
```

---

## ⚠️ 注意事项

1. **不要修复用户可见的消息**
   - 如果print用于显示给用户，应该使用Toast或Alert
   - 不要用#if DEBUG包裹

2. **保留关键错误日志**
   - 生产环境也需要记录关键错误
   - 使用Logger.error（会自动处理）

3. **测试修复后的代码**
   - 确保DEBUG模式正常工作
   - 确保RELEASE模式不输出调试信息
