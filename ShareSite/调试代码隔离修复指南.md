## 🔧 修复方法

### 方法1：手动修复（推荐，精确）

#### 步骤1：识别调试print语句

```swift
// ❌ 需要修复
print("用户token: \(token)")
print("✅ 操作成功")
print("❌ 错误: \(error)")

// ✅ 已修复
#if DEBUG
print("用户token: \(token)")
#endif
```

#### 步骤2：批量修复单个文件

对于每个文件：
1. 打开文件
2. 查找所有 `print(` 
3. 判断是否为调试信息
4. 添加 `#if DEBUG` 和 `#endif`

#### 步骤3：使用查找替换（在Xcode中）

1. 打开文件
2. Cmd+F 查找 `print(`
3. 逐个检查并添加保护

---

### 方法2：使用Logger工具类（长期方案）

已创建 `Utils/Logger.swift`，可以逐步替换：

```swift
// ❌ 旧代码
print("网络请求: \(url)")

// ✅ 新代码
#if DEBUG
Logger.network.debug("网络请求: \(url)")
#endif
```

## 🔍 识别规则

### 需要保护的print（调试信息）

```swift
print("🔍 调试信息")
print("📊 统计数据: \(data)")
print("✅ 操作成功")
print("❌ 错误: \(error)")
print("🔄 状态更新")
```

### 不需要保护的print（用户消息）

如果print用于显示给用户，应该改为：
- Toast提示
- Alert弹窗
- 其他UI组件

---

## ⚠️ 注意事项

1. **不要保护错误日志**
   - 关键错误应该使用Logger.error（会自动处理）
   - 或保留在生产环境

2. **检查print的用途**
   - 如果是调试信息 → 添加#if DEBUG
   - 如果是用户消息 → 改为Toast/Alert
   - 如果是关键错误 → 使用Logger.error

3. **测试修复后的代码**
   - DEBUG模式：确认日志正常输出
   - RELEASE模式：确认不输出调试信息

## 🚀 快速修复示例

### 示例1：单个print语句

```swift
// 修复前
print("用户登录成功")

// 修复后
#if DEBUG
print("用户登录成功")
#endif
```

### 示例2：多个print语句

```swift
// 修复前
print("开始请求")
print("请求URL: \(url)")
print("请求完成")

// 修复后
#if DEBUG
print("开始请求")
print("请求URL: \(url)")
print("请求完成")
#endif
```

### 示例3：在函数中

```swift
// 修复前
func fetchData() {
    print("开始获取数据")
    // ... 代码 ...
    print("数据获取完成")
}

// 修复后
func fetchData() {
    #if DEBUG
    print("开始获取数据")
    #endif
    // ... 代码 ...
    #if DEBUG
    print("数据获取完成")
    #endif
}
```
